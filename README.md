# Worksoft tree demo

An Angular 15 named-list project-member picker. The reusable tree renders plain nodes and emits user intent. A plain TypeScript helper owns tree state and lazy loading; the project-member controller supplies loaders and sends membership changes to an asynchronous data-source adapter.

```sh
nvm use
npm ci
npm start
npm test
npm run build
```

## Component integration

Import `TreeModule` into your standalone component or NgModule:

```html
<ws-tree
  [nodes]="treeNodes"
  label="Project members"
  (expand)="onNodeExpand($event)"
  (selectionChange)="onSelectionChange($event)"
></ws-tree>
```

Both outputs emit the original `TreeNode`. The tree does not fetch data or toggle membership itself. The module also exports `TriStateCheckboxComponent` (`ws-tri-state-checkbox`), a controlled checkbox with `status`, `disabled`, and `label` inputs and an `activate` intent output.

```ts
const helper = new TreeHelper();
const root = helper.initializeTree();
const chain = helper.createNode('10 Hovedkontor', true, false, { chainId: '10' });
helper.applyCounts(chain, { members: 2, total: 10 });
helper.insertNodesAtRoot(root, [chain]);
helper.configureLazyLoad(chain, (_nodeId, chainId) => loadBranchNodes(chainId), ['10']);

// Expansion executes the loader once; successful empty responses are cached too.
helper.toggleExpansion(chain);
// Call helper.destroy() when its owning controller is destroyed.
```

`loadBranchNodes` is an application callback returning `Observable<TreeNode[]>`. The helper subscribes and attaches the returned children, maintaining their parent references and sibling indexes. Node IDs are generated by the helper and are separate from business IDs. `hasChildren` describes expandability; `isLoaded` records successful completion. Collapsing closes descendants while retaining loaded objects.

## Membership behavior

- Chains show disabled informational tri-state checkboxes. They cannot initiate bulk changes.
- Unchecked or partial branches add all remaining people; checked branches remove everybody in that branch. Empty branches are disabled.
- Person checkboxes represent confirmed project membership. A person is identified by branch ID plus employee ID.
- Every action sends an asynchronous request. The checkbox retains its previous state until success; there is no Save button.
- While a mutation is pending, actionable controls in that chain are disabled to prevent conflicting updates. Other chains remain usable. Failure, timeout, or cancellation releases the pending state; failures show a separate membership retry action.

`WeekViewFakeDataService` contains five chains, ten branches, and 28 initially unselected employees. It owns membership state for the demo component's lifetime and simulates a 150ms backend response. Data resets on page reload. This is an in-memory backend stand-in, not HTTP persistence.

Initialization loads only chains with member/total counts. Expanding a chain loads branches with counts; expanding a branch loads people with membership flags. No full employee snapshot is fetched. Mutation responses supply authoritative branch/chain counts, including unloaded people. Browsing groups display `X / Y employees selected`.

## Search and accessibility

Search remains inside the tree, debounced by 300ms. The adapter caps results at 300 and reports whether more matches exist. Results follow the listing order and are grouped in one pass using maps. Search nodes start expanded and loaded, with lazy loading disabled. Only person checkboxes are shown; all group counts are hidden.

Search and browsing share confirmed membership changes. Clearing search restores the same browsing objects and expansion state. Superseded queries are canceled immediately. Reads that overlap a membership change are discarded and refreshed before they can install stale values.

Every visible row has `tabindex="0"`. Arrow Up/Down use the helper's visible-node traversal and registered row focus handles, including movement between chains. Right Arrow expands a collapsed group; Left Arrow collapses an expanded group. Neither key changes leaf nodes. Native buttons and checkboxes retain Tab/Space/Enter behavior; Space/Enter on a row invokes an allowed membership change. Rows unregister their handles when removed. Loading and errors use status regions.

## Files and backend integration

Copy `src/app/tree` for the reusable model, helper, recursive renderer, row component, checkbox component, and module. `additionalInfo` can carry application records without the renderer interpreting them. The controller instantiates `TreeHelper`; it is not an Angular service.

The domain example remains in `src/app/demo`. Replace `OrganisationDataSource` with a project-scoped adapter implementing the read, capped search, and explicit membership mutation contracts. Chains are directory context, not stored member identity. Organisation-wide/chain-wide/branch-wide project configuration and pricing are outside this named-list picker.

Existing `[tree-debug]` logging and debugger statements remain at renderer/host event boundaries. See [DEVELOPER_README.md](DEVELOPER_README.md) for contracts, request ordering, and verification.
